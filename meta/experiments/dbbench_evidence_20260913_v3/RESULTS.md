## 成本与解读补充

三轮提案共 162 次可见模型请求；累计证据读取 525,002 字符（包含重复读取和工具包装），各轮独立证据均在 80k 字符内。Qoder 未提供有效 token 用量，不能给出总推理 token 或货币成本。第一轮有一次 Bash 列目录请求，工具返回 error；未发现成功执行或显式越界读取。其余轮无显式工具/路径越界记录，详见 proposer_audit.json。

正式运行 166 episode，1,127,614 agent tokens，transport 重试 0。前两次检索实现错误中断各花费 50 道基线（280,009 / 299,843 tokens），未计分候选。包含这些排错成本，总计 266 episode、1,707,466 agent tokens、217 次提案模型请求，见 costs.json。没有把这些排错成本隐去。

第一轮和第三轮对起点均为 0 胜 / 0 负；第二轮仅筛查 0 胜 / 1 负，其全量分数未知。INSERT 仍 5/17，UPDATE 仍 12/17。当前主线保留 baseline.py，它与上轮已接受 candidate_03.py 完全相同。

这次实跑验证了预算、检索、筛查和严格接受能形成完整流程，**没有验证迭代质量或泛化提升**。相较上一批原始阅读流程的三轮日志（累计 720,376 证据字符、154 次提案请求），本次累计阅读更少，但提案请求更多；起点不同且缺乏匹配对照，不能归因为新流程更省成本或更有效。

后续优先改进的方向（本轮未改协议/未新增模型实验）：

- 把公共系统说明和 H3 定义单独存一次，按回合检索只返回增量，避免固定重复内容耗尽补充阅读额度。
- 让失败代表与成功对照成对占用预算。本轮详情分别只返回 3/4/4 个任务，摘要中的成功对照不等于充分读过完整反例。
- 在真实评分前验证提案所述机制确实改变了对应公开案例行为，区分“解析缺陷消失”与“最终任务解决”；保留接口回放和全量接受门槛。
- 保留未接受候选的局部行为变化，改进后续假设选择，而不是仅根据总分重复选择相似修复。
