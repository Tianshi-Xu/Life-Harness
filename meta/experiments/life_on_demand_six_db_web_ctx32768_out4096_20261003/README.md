# 新版 Life：六轮，32768 总上下文 / 4096 单次输出

DBBench / WebShop 各六轮，H2～H5 策略内容从空开始。每轮冻结训练批次 50 条（b0～b5），全部当前训练案例按需读取，不限制案例数量或总字符。

Flash 全局并发最多 8，本地 Qwen 每域最多 50 个 episode worker。输入（含系统、工具、工具结果、已有真实 reasoning）＋输出的总上下文最多 32768；单次输出最多 4096，包含本次 reasoning。固定官方 DeepSeek 编码/tokenizer 离线预计数并留 512 token 余量，响应后核对 API 实际使用量。Qwen 用其本地 tokenizer 同样实施总上限。

正常超限记失败，不扩容、不追加重试。有效候选必须通过本地回放/fixture 校验，再与 incumbent 同批完整 50 题比较，仅严格提高才接收。提案超限或预算内未产生有效候选时，该轮记“未产生候选/候选未测”，保留 incumbent，继续下一轮；不编造候选分数，不接收未验证的代码。

此前两次未完成提案的输出配置不同，完整保留，单列为启动尝试，不混入本配置的六轮统计，也不继承其策略/诊断。首轮两域的 100 个空 harness 基线 episode 逐调用满足新长度要求，因此哈希复用，不重跑。

两域六轮结束并封存后关闭优化器连接，再用本地 Qwen 测完整 DB 300 / WebShop 200 条测试题。测试信息不进入优化器。逐轮结果在 TRAINING.md / COMPARISON.md，失败在各域 failures/ 下保存 receipt；真实 key 只在宿主 broker 内存，不写入实验文件或子进程环境。
