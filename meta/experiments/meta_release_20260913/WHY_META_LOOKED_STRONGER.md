# 为什么这轮 Meta 看起来比 Life 迭代更强

结论不是“Meta 算法已经证明优于 Life”。当前最可信的判断是：Meta 的诊断自由度与推理预算更大，确实找到了更具体的缺陷；同时 DB 的接口起点不公平放大了差距。ALF 的同标准集实际差距只有 1/109。

## 先把结果放在同一尺度

- ALF：Life 已发布版历史为 103/109；Meta 第六轮 104/109。逐题比较是 Meta 1 胜 / 0 负，差距很小。Meta 相对原始 H2345 是 4 胜 / 0 负，双侧配对精确检验仍约 p=0.125，单 trial 不足以证明稳定优势。
- DB：本次原始 H2345 186/300，Meta 190/300，9 胜 / 5 负，双侧配对精确检验约 p=0.424。它是小幅净增，不是压倒性提升。
- Life 统一接口 DB 版本曾为 148/300，但该版本把原发布 Runtime 的结构化 task type / schema 样例入口改成从公开题面推断，92/200 道写操作被归成查询；INSERT 54→33、UPDATE 86→72。Meta 从保留结构化入口的原始 H2345 开始，因此 `190 vs 148` 主要混入了接口迁移损失，不能归为迭代流程胜负。

## Meta 这次真正占优的部分

1. 推理预算更高。Meta 六轮 ALF 有 777 次、DB 有 820 次可见 proposer 请求；Life 统一接口三轮分别只有 95 和 107 次。Meta 每轮还固定一个分析 Agent 加一个实现 Agent，Life 的有界流程禁止委派。
2. 证据访问更宽。Meta 可检查本次全部公开轨迹、所有历史候选和原始源码，并用 Bash 写分析/回放脚本。Life 后续流程每轮最多 80k 个不同证据字符，实际 DB 每轮只返回 3/4/4 条按需任务详情，而且禁止 shell。Meta 因而能从“失败组”继续追到精确状态变量、调用解析器和逐回合反例。
3. 搜索空间更宽。Meta 可改任意 Runtime/helper，并使用 `transform_response`；它找到的纯文本动作恢复、JSON/XML 容错、控制字符 KeyError 都是协议边缘层问题。Life 要求每轮归属一个 h2–h5 层、限制导入和提示形态，安全性与可审计性更好，但降低了发现低层 glue bug 的机会。
4. 样本覆盖更宽。Meta 停滞即换题，ALF 看过 100、DB 看过 150 道不同训练题；Life 最新有界 DB 实验固定在一批 50 题跑三轮。后者连续提出的机制在这批上都没有改变成功位，继续读同一批信号的边际收益已经很低。
5. Meta 每轮都做完整 50 题评测。Life 先做 16 题筛查，第二轮因 0 胜 / 1 负没有全量。筛查显著省 solver 成本，但可能漏掉稀疏、长尾的正收益。Meta 用更多评测成本换取了更低的错杀概率。
6. Meta 的工作方式更贴近软件调试。它先写离线分类和 replay，证明某个分支会触发、成功轨迹不受影响，再改一个机制。Life 的自动分组目前多是 `unclassified`、`sql_syntax`、`budget_exhausted` 这类症状，摘要质量还不足以直接提供根因。

## 应该吸收到 Life 的改进

- 保留 h2–h5 作为发布接口和责任边界，但允许候选在层内修改关联 helper、解析器和状态机；增加一个明确的 response/tool-call normalization 子接口，避免 `transform_response` 能力只能存在于旧 Runtime。
- 先恢复迁移等价性再比较方法。DB 应把原发布版本合法拥有的结构化 task type/schema 上下文，通过冻结、只读的公开 `TaskContext` 传给四层 Harness；不能让候选重新从题面猜类型。每次接口迁移必须先在固定回复上做到输入/决策等价，再开始迭代。
- 把 Meta 的“两角色”纳入有界流程：一个只做根因定位和反例验证，另一个只实现；总证据预算不必取消，但应给分析脚本一个只读、无网络、受路径限制的沙箱。
- 停滞后轮换训练批次，同时保留一小组 anchor tasks 防遗忘。新批复测 incumbent，同批决策；接受候选前再检查 anchors，避免只在新批局部提升。
- 将筛查从单一 16 题改成“高风险回归 anchors + 假设命中任务 + 随机任务”，并保留周期性全量；对已经离线证明只影响极少分支的候选，降低筛查错杀权重。
- 强化 evidence index：自动给出“首次分歧回合、最后一次有进展、无工具调用、解析异常 stack、hook 决策与相似成功对照”，而不仅是粗粒度失败标签。保留未接受候选的局部行为变化供下一轮使用。

更公平的流程对照应从同一份四层等价 H2345、同一批训练题、相同六轮 proposer/solver 预算开始，一边用 Meta 原始检索，一边用升级后的 Life 证据流程；最终只在预先冻结且未用于诊断的测试集比较。当前实验尚未满足这些条件。
